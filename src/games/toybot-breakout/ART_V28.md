# V28 · 统一机甲美术、动作与材质反馈

## 本轮交付

1. 统一角色的白/海军蓝玩具金属、左上受光与描边层次；敌人与地图保留已有 AI 素材，统一接触阴影与克制的高光处理。
2. 脉冲、重炮、战刃分别采用紧凑、厚重、修长剪影。每种有基础/强化两套战斗形态；第一次获得武器、装甲或核心强化就切换结构。首页/机库/暂停/胜利立绘另有三模块的八种独立装配组合。
3. 每种普通机甲的图集为 8 列 × 8 行：基础跑/待机/攻击/闪避、强化跑/待机/攻击/闪避，共 192 帧。跑图保留腿部跑姿，攻击上半身与发射时刻同步；首领战改为站定姿态，换道使用侧闪。蓄力窗口按实际攻击间隔压缩，不改变攻击频率。
4. 新增金属火花、护盾局部涟漪、碎甲、分段爆炸四类八帧特效。沿用真实命中与防御事件，不用装饰动画触发伤害。低画质维持既有反馈预算。
5. 新增 AI 接触阴影、脚尘、前景管线视差，增强门脚反射与地面阈值。奖励门仍使用已校正的 85% 接地点、深度排序和原判定。
6. 五首领共 40 格新图集：铸炉开胸、蜂后展翼、堡垒开盾、先知展开光环、帝皇展开冠翼。第二阶段在攻击/冲刺/收招时保持展开形态。原出场和战败图集继续使用，既有技能/伤害/发射源保持权威模拟。
7. 击破后回收物飞向小队；装配时点亮地面组装环与机体；胜利展示本局机型、装备和按受伤比例变化的战损划痕。回收动画只是既有收益的视觉回执，不重复发放零件。

## 设计与实机核对

概念图：`art-source/art-direction-v28.png`。它用于材质、相机、色彩和接地关系的方向校验，没有被当作界面截图贴进游戏。

通过 IAB 读取实际页面、点击控件并截图，随后用 `view_image` 同轮检查概念图、正式首页截图和 390×844 战斗截图。浏览器默认 1280×720、手机 DOM 390×844；概念原生 941×1672 没有作为游戏视口，采用常见手机尺寸检查实际可操作性。临时视口已恢复，预览未写入玩家存档。

| 对照点 | 结果与处理 |
| --- | --- |
| 材质/配色 | 白/海军蓝基底，脉冲青、重炮橙、战刃紫；已替换首页旧立绘配色 |
| 场景层次 | 小队接触阴影、三轨透视、门脚反射；前景仅经过左右边缘 |
| 角色与装备 | 同尺寸队员；实际点击机库选择战刃后，首页更新对应立绘与模块组合 |
| 动作与事件 | 发射帧不提前判伤；首领待机不跑；侧闪、强化地环、四种材质反馈通过真实组件检查 |
| 首领阶段 | 五个图集行索引及展开后的攻击帧均检查；修复旧攻击图覆盖第二阶段造型的问题 |
| 页面文字/按钮 | 生产首页、暂停、胜利既有文案与顺序不变；没有把概念中的示例数值当真实数据；手机技能按钮 87×87、换道按钮高 44px，无横向溢出 |
| 胜利展示 | 修复旧 `showcase > span {display:none}` 隐藏新立绘的问题；奖章缩至角标，机体与划痕可见 |

有意保留的差异：五关现有地图与现有驾驶舱/文字布局；首领保持当前玩法所需的屏幕尺度，未采用概念图占据半屏的巨型比例，以留出预警和躲避空间。动态警告轮廓、进度条和交互文字继续由代码绘制，角色、材质效果和前景使用 AI 位图。以上是既有产品适配，不是缺失素材。

验收：216 项模拟/动作/资源测试通过；游戏目录 ESLint 与 Vite 生产构建通过。项目全量 TypeScript 仍有既存的共享 `App.tsx` 未用 React、`LogService.ts` 的两处 nullable string 错误，游戏模块无新增类型错误。没有 Facebook 测试入口，本轮结论限于本地浏览器，未声称平台真机验收。
