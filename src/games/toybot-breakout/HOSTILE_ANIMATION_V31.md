# V31 小怪与首领独立动作

原来的巡逻机只有 3 帧循环，其余小怪主要是单张立绘；首领按战斗状态切换少量姿态。本轮改为十二类独立的 AI 透明动作图集，并由同一战斗时钟播放，取消敌方身体上的 CSS 翻页和重复摇摆。

## 动作设计

| 单位 | 移动 | 蓄力/攻击 | 受击 |
| --- | --- | --- | --- |
| 巡逻机 | 转子倾斜、稳定悬浮 | 短炮交替后坐力 | 倾斜后重新稳定 |
| 突击蜂 | 快速摆翼、前倾 | 收紧机翼后前扑 | 翼面摆动并回正 |
| 狙击哨 | 稳定追踪 | 枪管伸出、镜头蓄能、单发后坐力 | 护住长枪、机体回正 |
| 轰炸机 | 重型吊舱随动 | 弹舱展开、投射、关闭 | 吊舱收拢卸力 |
| 维修机 | 机械爪短步与悬浮 | 聚能爪展开，实际修复后播放脉冲 | 双爪保护核心后展开 |
| 奔袭机器人 | 交替迈腿奔跑 | 蹲身蓄力、双臂撑地前扑 | 护住独眼核心并回正 |
| 震荡路障 | 展开并稳定落地 | 侧甲压地、蓄能、震荡释放 | 装甲片卸力下沉并复原 |
| 铸炉监工 | 重踏、肩部随动 | 收拳蓄热、重拳/熔炉释放 | 厚重躯干后仰回正 |
| 苍穹蜂后 | 振翼、侧倾 | 炮口展开、翼炮齐射 | 合翼防护、恢复悬停 |
| 赤铁堡垒 | 持盾负重迈步 | 架盾、开启炮口、后坐力、合盾 | 盾面吸收冲击、躯干下沉 |
| 风暴先知 | 甲片随悬浮移动 | 展开晶体、双手聚能与释放 | 甲片内收防护 |
| 星核帝皇 | 稳重迈步、裙甲随动 | 抬手蓄能、裁决挥落、收招 | 扭身防御后恢复站姿 |

每段 8 帧；七种敌方小单位各 32 帧，五位首领各 64 帧（含两阶段），总计 544 帧。首领按当前关卡选择各自资源和时序，小怪按实际种类选择；首领召唤的小机器人、路障也沿用对应的机器人身体，而不是炮弹图集。

## 衔接与判定

- 每个实体只有一个身体节点。切换图集行时不叠加另一个上半身、透明副本或残影。
- 同一机体的整格坐标通过中央装甲模板平移对齐；不对肢体做程序绘图。低相似度的刻意转身保留原始位置，避免错误拉扯。对齐参数在 `hostile-registration-v31.json`。
- 蓄力动画跟随真实预警剩余时间；攻击跟随真实发射时间戳或小怪攻击记录。持续场地技能不会让身体无限循环发射，连发只在实际新发射时重新播放。
- 突袭接近和接触动作与原有突袭时间相对应。位移动画使用已有换列时间；不新增会影响命中的视觉位移。
- 真实伤害触发每实体独立的 6 步受击片段、14 步重置间隔，密集炮弹不会不断重启第一帧。受击不会取消已有蓄力/发射；关键攻击期间保留该动作，并用单机体亮度反馈命中。
- 维修特效只在真实治疗发生后播放。击败首领后保留当前阶段机体，使用受损、倾倒和淡出的表现，避免切回旧造型。
- 暂停冻结战斗时钟；低动态模式固定动作帧并去掉额外位移/闪亮。死亡实体仍按原有规则及时删除，不因受击动画延后删除。
- 新增 `hostileReactions` 只记录表现计时，不改变血量、伤害、攻击间隔、目标或轨道判定；过期记录会清除。

## 素材与复现

运行素材：`public/games/toybot-breakout/optimized/boss-*-motion-v31.webp` 和 `enemy-*-motion-v31.png`。

首领运行图为保留透明度的 WebP，2048×2048、单格 256 px；未压缩的对齐 PNG 保留在 `art-source/boss-*-atlas-v31.png`。小怪为 1024×512、单格 128 px。首领高清原图按阶段拆为 `art-source/boss-*-phase1-v31.png`、`phase2-v31.png`，以改善在手机中放大展示的细节；早期合并图保留为源草稿。小怪原图在 `art-source/enemy-*-motion-v31.png`。提示词在 `ART_PROMPTS_V31.json`，包含高清迭代记录。

运行 `pwsh -File src/games/toybot-breakout/optimize-hostiles-v31.ps1` 可重新进行机械裁切、注册、拼接与透明 PNG 导出及 WebP 编码（需要支持 System.Drawing 的 PowerShell/.NET；当前环境使用 PowerShell 7 和已有 Pillow，未新增依赖）。首领只预载当前关卡的图集。

`hostileMotionV31.ts` 是生产动作采样入口，`motion.ts` 绘制结果。已有 `motion-review.html` 内的“敌方独立动作”可分别查看十二类单位的移动、蓄力、攻击和受击，也可检查首领两阶段；不写玩家存档，不注册到发布游戏路由。

## 本地验收

242 项回归测试通过；本轮修改文件 ESLint 通过；Vite 构建通过。浏览器逐项检查十二种实体的独立图集及移动、蓄力、攻击、受击，并检查首领两阶段。真实怪潮场景有 24 只小怪，逐实体均只有一个身体；五关首领分别加载自己的资源。390×844 手机尺寸无水平溢出，最终验收页无运行错误。首领透明 WebP 约 1.1–1.4 MB/关，保留 2048×2048 尺寸。

全项目 TypeScript 检查仍有共享 App.tsx 的未使用 React 导入，以及 LogService.ts 的两处 nullable string 错误；新增游戏文件无类型错误，按仓库约定未修改共享模块。Facebook 真机尚未验收。
